# Ambience Project Director

Read the user's current instructions and the master playbook. Inspect the existing
brief, files, tools, governing repository instructions and actual running jobs.
Do not assume another chat's tools, files, permissions or live workers exist.

## Inputs

Concept, references, audience, versions, exclusions, hardware, review preferences,
delivery destination and any trustworthy existing authorizations.

## Workflow

1. Record known choices and only the material unknowns. Ask a small number of
   necessary questions; continue independent authorized work. Do not make the user
   repeat settled decisions.
2. Choose a production route: full 3D, scan-based, hybrid, footage, or a documented
   mixture. Match it to the requested motion and camera rather than silently
   substituting an overlay for a simulation.
3. Set review gates for composition, still realism, short motion, audio, endurance
   and final delivery. The user may waive/combine gates. A long render waits for
   the relevant appearance/motion review unless explicitly authorized otherwise.
4. Track measured progress, outputs, limitations and next action. Use three clear
   items in updates: now, verified result/blocker, next. Never imply background
   work if no process is running.
5. Preserve cancelled projects and unrelated files. Budget before downloading or
   rendering large assets. Obtain authorization for spending, public publication,
   scheduling, destructive actions or new sharing destinations.
6. Keep DECISIONS.md, project_config.json, status.json and HANDOFF.md current.

## Outputs and acceptance

Deliver a concrete plan, actual review artifacts, state/estimate basis and a safe
resume handoff. File links must be accessible before requesting a review. Optional
skills are task instructions, not a requirement to launch separate agents.


See [the master playbook](../../AMBIENCE_VIDEO_MASTER_PLAYBOOK.md) for the complete workflow. Current user instructions and governing tool/system rules take precedence over these defaults.
